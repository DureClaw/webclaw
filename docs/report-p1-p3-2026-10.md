## 2. 항목별 구현

### P1-1. 정책 계층 — `guard.js`
- **설정 주체는 사람뿐**: 팝업 "🛡️ 정책" 또는 `config.local.json`의 `policy`. 마커는 `[POLICY]`로 *읽기만* 가능.
  에이전트가 자기 안전장치를 끌 수 없게 한 것이 핵심 설계.
- `deny` 도메인: 읽기·조작·`[OPEN]`·`[FETCH]`·`[DOWNLOAD]`·CDP 릴레이 전부 `policy_denied`.
- `mode:"ask"`: 사이트별 첫 변경 동작은 HUD에 승인 요청 → 사용자가 채팅에 `/allow`(이번만)·`/allow-site`(브라우저 세션 동안 이 사이트)·`/deny`.
  120초 무응답 → `approval_timeout`. 승인 요청은 버스 인박스에도 알려 마스터가 대기 중임을 안다. 읽기는 묻지 않음.
- `confirmRisky`: 대상 요소의 텍스트를 읽어(결제·구매·주문·송금·이체·삭제·탈퇴·해지·pay·checkout·delete…) 매번 승인.
- **감사 로그**: 모든 마커(act/read/open/fetch/download/webmcp/relay)의 결과·reason·대상·호스트를 1,000건 링버퍼로. `[AUDIT] [n]`, MCP `webclaw_audit`.

### P1-2. 녹화·리플레이 — `guard.js`
- `[REC] on <라벨>` 동안 변경 동작마다 프레임(시각·동작·대상·결과·CDP 스크린샷 q30)을 `storage.session`에 기록(이미지 40장, 프레임 300개 상한, 용량 초과 시 텍스트만).
- `[REPLAY] [경로]` → 자기완결 HTML 타임라인을 다운로드 폴더에 저장.

### P1-3. 벤치마크 — `bench/`
- 결정론적 픽스처 10종: 폼 로그인, 검색+표 추출, 3단계 마법사(라디오·셀렉트·체크박스), 프레임워크식 controlled input, 교차 출처 iframe, shadow DOM, 3페이지 수집, 파일 업로드, 늦게 뜨는 콘텐츠, 모달 확인.
- 같은 과제를 세 전략으로: **step**(아웃라인→@ref→동작, 도구 호출당 마커 1개) · **run**(`[RUN]` 1회) · **relay**(Puppeteer가 CDP 엔드포인트로).
- 지표: 성공·시간(성공 반복 중앙값, 페이지 로드 후부터)·왕복 수·에이전트에게 돌아간 바이트(≈토큰×4).

### P2-1. CDP 호환 엔드포인트 — `relay.js`(확장) + `bridge/cdp-relay.cjs`(미니버스)
- 미니버스가 `http://127.0.0.1:4777/cdp/<secret>`에서 DevTools 디스커버리(`/json/version`)와 WebSocket 엔드포인트를 제공(`webclaw cdp-url`).
- 브라우저 수준 `Browser.*`·`Target.*`는 미니버스가 에뮬레이션: getTargets, setAutoAttach(flatten), attachToTarget, createTarget, closeTarget, getTargetInfo, setDiscoverTargets 등.
  페이지 세션 명령은 버스 `cdp.call` → 확장 `chrome.debugger.sendCommand`, 이벤트는 `chrome.debugger.onEvent` → `cdp.event`로 역방향 전달.
  자식 세션(OOPIF)은 Chrome의 실제 sessionId를 그대로 사용.
- **노출 범위**: 기본은 에이전트 Space "cdp"의 탭만(`relayScope:"all"`로 확장). 사용자 탭을 CDP 클라이언트가 집어가지 않음.
  새 브라우저 컨텍스트는 거절(실제 프로필이므로), `Browser.close`는 연결만 끊음.
- **보안**: 경로에 secret 필요, Host 헤더가 루프백이 아니면 403(DNS 리바인딩 방지), 웹 페이지 Origin의 WS 업그레이드 거부, raw `[CDP]` 금지 목록과 정책 금지 목록 적용(페이지 범위 `Target.setAutoAttach` 등 3개만 예외), 연결은 감사 로그에 기록.

### P2-2. learnings 공유·레시피 자동 저장 — `core.js`, `learn.js`, `bin/webclaw.cjs`
- `[RUN]` 첫 줄 `// @save <도메인>/<이름>` → 스크립트가 **성공했을 때만** 레시피로 저장(결과 JSON에 `"saved"`).
- `[LEARNINGS] export | import`, CLI `webclaw learnings export [파일] | import <파일> | push [이름] | pull [이름]`.
- push/pull은 DureClaw 버스의 스킬 레지스트리 계약(`/api/skill-registry`, `/download/:name`, `/publish`)을 사용하고, 미니버스가 같은 계약을 구현(`~/.webclaw/registry.json`에 영속).

### P2-3. CDP minimal 모드 — `cdp.js`
- `prefs.cdp`: `auto`(기본) · `minimal` · `off`. minimal에서는 CDP 없이는 안 되는 경우(`[CDP]`, `[UPLOAD]`, CSP에 막힌 `[JS]`)에만 붙고 동작 직후 즉시 detach → "디버깅 중" 안내줄이 그 순간에만 보인다. 릴레이 탭은 고정(pin)되어 유휴 해제 제외.

### P3-1. WebMCP 중계 — `webmcp-shim.js` + background
- MAIN world·document_start 콘텐츠 스크립트를 `chrome.scripting.registerContentScripts`로 등록(팝업에서 끌 수 있음).
  네이티브 `navigator.modelContext`가 있으면 `provideContext`/`registerTool`/`unregisterTool`/`clearContext`를 감싸 기록하고, 없으면 폴리필.
- `[WEBMCP] list` / `[WEBMCP] call <tool> {json}`, MCP `webclaw_webmcp_list`/`webclaw_webmcp_call`. 호출은 변경 동작으로 취급되어 정책(ask·deny)을 따른다.

### P3-2. Web Bot Auth 신원 — `identity.js`
- WebCrypto Ed25519 키 생성(`[IDENTITY] init`), RFC 7638 thumbprint를 keyid로, RFC 9421 서명 베이스(`@authority`, `signature-agent`), `tag="web-bot-auth"`, created·expires·nonce.
- 사람이 팝업에서 켜면 확장 자신의 `[FETCH]`에 `Signature-Input`/`Signature`/`Signature-Agent` 부착. `[IDENTITY]`가 `/.well-known/http-message-signatures-directory`용 키 디렉터리를 출력.

### 3.3 벤치마크 — `bench/results/RESULTS.md`

| 전략 | 성공 | 시간(중앙값 합) | 왕복 | 에이전트 수신 바이트 |
|---|---|---|---|---|
| step(마커 1개/호출) | 30/30 | 2,154 ms | 41 | 3.2 KB |
| run(`[RUN]` 1회) | 30/30 | 2,020 ms | **10** | **0.4 KB** |
| relay(Puppeteer→CDP 엔드포인트) | 30/30 | 2,221 ms | (CDP) | — |

- push 전환 **전** 첫 측정: step 12,347 ms, run 4,358 ms. 과제와 무관하게 run이 256~258ms로 고정된 것을 보고 폴링 양자화를 진단 → 수정.
- 해석: 도구 계층 지연은 이제 왕복당 ~10ms 수준이라 로컬에서는 전략 간 시간 차이가 작다. 실제 에이전트 루프에서 차이를 만드는 것은 **턴 수 4배·바이트 8배 감소**(run)이고, 각 턴이 LLM 호출이므로 비용·지연은 그 비율로 벌어진다.
- relay는 페이지당 DOM 왕복이 Playwright/Puppeteer 자체 프로토콜이라 왕복·바이트 지표는 비교 대상에서 제외.

## 4. 한계와 정직한 단서

1. **벤치마크는 LLM이 없는 도구 계층 측정**이다. ego의 31과제(LLM·실사이트·채점 모델) 수치와 직접 비교할 수 없다. 실사이트·LLM-in-the-loop 버전은 남은 과제.
2. **E2E의 "사람"은 하네스가 재현**했다(서비스 워커로 정책 저장, HUD 입력창에 키 이벤트). 실제 팝업 UI 클릭과 실제 사람의 입력은 이번 자동 검증에 포함되지 않았다. 팝업 정책 UI는 수동 확인이 필요하다.
3. **CDP 엔드포인트는 standalone 모드 전용**이다. DureClaw 버스를 거치는 bus 모드에서는 `cdp.call`/`cdp.event` 중계를 버스가 하지 않는다.
   검증 범위는 Puppeteer 25.15·Playwright 1.64의 기본 페이지 조작이고, 다운로드·다중 컨텍스트·Service Worker 타깃·`context.cookies()`(브라우저 수준 Storage)는 미지원이거나 미검증이다.
4. **Web Bot Auth는 확장 자신의 `[FETCH]`만 서명**한다. 페이지 이동 요청은 서명할 수 없다. 헤더 형식은 초안(Cloudflare 배포형)을 따랐고 표준이 아직 움직이는 중이다. 실제 Cloudflare 검증 엔드포인트에는 키를 등록하지 않아 시험하지 않았다.
5. **WebMCP 셈**은 모든 페이지에 `navigator.modelContext`를 정의한다(없을 때). 기능 탐지를 하는 사이트는 "WebMCP 지원 브라우저"로 인식할 수 있다. 팝업에서 끌 수 있다. Chrome origin trial의 실제 API와 세부가 다를 수 있다(초안 기준 구현).
6. **위험 동작 판별은 텍스트 정규식**이다. 아이콘만 있는 결제 버튼 등은 놓칠 수 있다. 엄격한 운영에는 `mode:"ask"`나 `deny` 목록을 함께 권장한다.
7. **실운영 버스에는 스킬 레지스트리 API가 없다**(HEAD 빌드). push/pull은 미니버스로 검증했고, 운영 버스에서는 `no_registry` 안내와 함께 파일 export/import로 대체된다.
8. **사용자의 실제 Chrome 확장은 아직 0.7.0이다.** 0.8.0/0.9.0 기능(정책 UI·WebMCP 셈·릴레이)을 쓰려면 확장을 리로드해야 한다.
